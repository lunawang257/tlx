# About ACM SAC 2025 paper "MAPLe"

## How to build

The code was tested on Linux Ubuntu and macOS with ARM chips. On macOS, install Xcode and use Homebrew to install all the other necessary tools. Please install the arm64 version of Homebrew if you intend to get the best possible performance on macOS.

Visual Studio Code can be used to configure CMake and build the individual tests for debugging.

To build all the binaries needed for the unit tests and performance tests, use:

   `tests/build_test.sh`

Because the parameters of the C++ templates must be available at compile time, the following C++ source files are generated by `tests/container/gen-all-options.py`:

   `tests/container/btree_speedtest_*_options.hpp`

The values of the parameter lists in `gen-all-options.py` include `btreemix_leaf_slot_max_list`, `btreemix_inner_slot_max_list`, `btreemix_value_size_list`, `leaf_slot_max_list`, `leaf_value_size_list`, and `slice_size_list`. Their values can be changed to support different combinations of the tree parameters.

If too many parameters are specified in `gen-all-options.py`, the compile time can be very long.

## How to run performance tests

### Manual method

To test end-to-end B-tree and MAPLe tree performance, use the `tests/tlx_container_btree_speedtest_btreemix` binary under `build/Release`. If you need to debug it, run the binary under `build/Debug`. The "--help" option will show you all supported command-line options. Some important parameters:

--maplize-threshold (-T): when this is 0, it will maplize every leaf, which means you will be testing a MAPLe tree. When it is set to 100, it will never maplize any leaf, meaning that it will be testing the standard B+ tree.

To test only the MAPLe leaf (not tree) performance, run the `tlx_container_btree_speedtest_*` binaries as mentioned in the section "Microbenchmarks".

### Automatic method

The automatic way to run performance tests is by entering this into the terminal:

   cd tests
   ./autopilot.py -d outdir -v 256 -v 128

This will use 256 bytes and 128 bytes as tree value sizes to perform the following steps:

1. Find the best parameters to run each type of tree (B-tree, MAPLe tree, MAPLe tree with one slice) for a balanced workload.
2. Run all tests with all parameters and write all the output into one file under the output directory "outdir".

### Semi-automatic method

The semi-automatic way to run performance tests is in `tests/run-many.sh`.

`run-many.sh` needs some manual customization before it can run:

1. Modify `gen-all-options.py` so that all the parameters you need will be generated.
   1.1 Run `gen-all-options.py` to generate the C++ files.
   1.2 Run `build_test.sh` to build the code. This script automatically invokes `gen-all-options.py`.

2. Set `paperMode` to 0 to run tests on all arguments (slotMax, sliceSize, etc.) for each tree.

3. Run `find-best-slotmax.py` to find the tree parameters for the best MAPLe tree performance and set them in the `BEST_MAPL_*` variables in `run-many.sh`.

4. Set `paperMode` to 1 to run tests on all threads to generate data needed by the paper.

## Code structure

### B-tree and MAPLe tree code

`tlx/container/btree.hpp` is the core file with the tlx B-tree and MAPLe tree code. Search for the variable `maplize_threshold` to find where the B-tree and MAPLe tree's logic differs.

The structs `Mapl` and `Slice` are the two main data structures of the MAPLe leaf.

### Test code

#### Debugging

The two main binaries that help debug the MAPLe tree are `tlx_container_btree_test` and `tlx_container_btree_speedtest_btreemix`.

`LOG_STR`, `log_*` are the functions or macros that log data into an in-memory buffer and console to aid in debugging. All of these log functions are compiled out in Release mode to avoid affecting performance.

If you see a deadlock, send a USR1 signal to the program using "kill" on another terminal. The program will print out the current log, which shows all of the lock/unlock actions from each thread.

#### Unit test code

The unit test code is in `tests/container/btree_test.cpp`. `test_mapl` tests the basic functions of the MAPLe tree leaf data structure. The `test_multithread` function tests the program with multiple threads and random operations. By manually changing variables such as `g_initial_size`, the multi-threaded tests can be customized.

#### Performance test code

There are two types of performance tests: microbenchmarks and end-to-end operation tests (`btreemix`).

##### Microbenchmarks

The microbenchmarks can measure the performance of specific operations on leaves. Each operation is performed by separate binaries:

1. `tests/tlx_container_btree_speedtest_maplize`: tests the performance of `maplize` and `unmaplize` operations. Invoked by the `RUN_MAPLIZE` macro.
2. `tests/tlx_container_btree_speedtest_update`: tests the performance of `insert` and `delete` operations. Invoked by the `RUN_UPDATE` macro.
3. `tests/tlx_container_btree_speedtest_lookup`: tests the performance of `lookup` operations. Invoked by the `RUN_LOOKUP` macro.
4. `tests/tlx_container_btree_speedtest_scan`: tests the performance of `scan` operations. Invoked by the `RUN_SCAN` macro.
5. `tests/tlx_container_btree_speedtest_rebalance`: tests the performance of `rebalance` operations. Invoked by the `RUN_REBALANCE` macro.

The actual code for all these microbenchmarks is in class `TestLeafPerf` in `tests/container/btree_speedtest_leaf.hpp`. As discussed earlier in the section "How to build", all the above macros (`RUN_*`) are instantiated in `tests/container/btree_speedtest_*_options.hpp` with different template arguments. These files can be generated by running `tests/container/gen-all-options.py`.

##### End-to-end Test `btreemix`

In the `btreemix` test, random tree operations with the required proportion are sent to the tree in a concurrent manner.

`Test_Set_MixedOp` in `tests/container/btree_speedtest_concurrent.hpp` is the main class that tests MAPLe tree performance. The `btreemix` test sends mixed operations (insert, delete, find, scan) to the tree and can be invoked by the `RUN_BTREEMIX` macro in `tests/container/btree_speedtest_main_template.hpp`.

The class `SpeedTestType` in `tests/container/btree_speedtest_controller.hpp` defines necessary tree, key, and value types, as well as utility functions such as filling random values into the key and value of the tree.

# tlx - Collection of C++ Data Structures, Algorithms, and Miscellaneous Helpers

tlx is a collection of C++ helpers and extensions universally needed, but not found in the STL.The most important design goals and conventions are:

- high modularity with as little dependencies between modules as possible.
- attempt to never break existing interfaces.
- compile on all platforms with C++ – smartphones, supercomputers, windows, etc.
- zero external dependencies: no additional libraries are required.
- warning and bug-freeness on all compilers.
- keep overhead down – small overall size such that is can be included without bloating applications.

## List of the most commonly used components:

- `CountingPtr` – an intrusive reference counting pointer
- `die()` - Simple Invariant Testing : `die()`, `die_unless()`, `die_if()`, `die_unequal()`.
- logger.hpp : `LOG`, `LOG1`, `LOGC`, `sLOG`, `wrap_unprintable()`.
- Miscellaneous: `timestamp()`, `unused()`, `vector_free()`.
- Algorithms : `merge_combine()`, `exclusive_scan()`, `multiway_merge()`, `parallel_multiway_merge()`, `multisequence_selection()`, `multisequence_partition()`.
- Data Structures : `RingBuffer`, `SimpleVector`, `StringView`, B+ Trees, Loser Trees, `RadixHeap`, `(Addressable) D-Ary Heap`
- Defines and Macros : `TLX_LIKELY`, `TLX_UNLIKELY`, `TLX_ATTRIBUTE_PACKED`, `TLX_ATTRIBUTE_ALWAYS_INLINE`, `TLX_ATTRIBUTE_FORMAT_PRINTF`, `TLX_DEPRECATED_FUNC_DEF`.
- Message Digests : `MD5`, `md5_hex()`, `SHA1`, `sha1_hex()`, `SHA256`, `sha256_hex()`, `SHA512`, `sha512_hex()`.
- Math Functions : `integer_log2_floor()`, `is_power_of_two()`, `round_up_to_power_of_two()`, `round_down_to_power_of_two()`, `ffs()`, `clz()`, `ctz()`, `abs_diff()`, `bswap32()`, `bswap64()`, `popcount()`, `power_to_the`, `Aggregate`, `PolynomialRegression`.
- String Algorithms : `starts_with()`, `ends_with()`, `contains()`, `contains_word()`, `trim()`, `replace_all()`, `erase_all()`, `join()`, `split()`, `split_view()`, `split_words()`, `union_words()`, `split_quoted()`, `join_quoted()`, `to_lower()`, `hexdump()`, `bitdump_le8()`, `word_wrap()`, `escape_html()`, `parse_uri()`, `parse_uri_form_data()`, `parse_si_iec_units()`, `format_iec_units()`, `ssprintf()`, `expand_environment_variables()`, `levenshtein()`, `hash_djb2()`, `hash_sdbm()`.
- Meta-Template Programming : `call_foreach()`, `apply_tuple()`, `vmap_foreach()`, `Log2Floor`, `FunctionChain`, `FunctionStack`, `is_std_pair`, `is_std_tuple`, `is_std_vector`, `is_std_array`, `TLX_MAKE_HAS_MEMBER`.
- Sorting Algorithms : `parallel_mergesort()` (experimental parallel merge sort from MCSTL), `sort_strings()` (using radix sort and multikey quicksort), `sort_strings_parallel()` (using parallel super scalar string sample sort), sorting network for up to sixteen elements.
- Backtrace Printing : `print_cxx_backtrace()`.
- Command Line Parsing : `CmdlineParser`.
- Multi-Phase Timer: `MultiTimer`, `ScopedMultiTimerSwitch`, `ScopedMultiTimer`.
- Fast Delegates : `Delegate` - a better `std::function<>` replacement.
- SipHash : simple string hashing `siphash()`
- StackAllocator : stack-local allocations
- Threading : `ThreadPool`, `Semaphore`, `ThreadBarrierMutex`, `ThreadBarrierSpin`.
